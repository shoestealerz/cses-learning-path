# Start here

This path assumes basic programming ability. Your rating and language are not required to use it. It is language-independent; use the language you compete with. There are 138 Core tasks, 92 Extension tasks, and 170 Specialist tasks.

## First session

1. Choose one task from each diagnostic row below, in order. Try independently; stop at your first real gap. Allow about 20–30 minutes per task, and split the diagnostic across sessions if needed. These are coaching defaults, not validated cutoffs.
2. A pass means an accepted implementation, a correct explanation, and a justified complexity bound without hints. A familiar memorized solution is not a diagnostic pass: use the alternate.
3. Start at the first failed row's module. For earlier modules, inspect the exit checks and sample unfamiliar tasks. Mark genuinely mastered tasks exempt; revisit them for completion later. You do not need to grind familiar warmups before learning something new.
4. If you pass all rows, sample modules 15–17 before starting Extension. Rating is only a weak shortcut; demonstrated knowledge decides placement.

## Where to read

Use Antti Laaksonen's [Competitive Programmer's Handbook](https://cses.fi/book/book.pdf) to learn a missing technique after an honest attempt. Read only the relevant chapter, close it, and derive your own solution. The curriculum ordering and practice intervals here are recommendations; the book is a reference, not evidence that this particular ordering is optimal. CSES task names and links come from the [official problem set](https://cses.fi/problemset/).

## A useful first week

Take the diagnostic, then spend your available non-contest sessions on the first weak module. Keep your Codeforces contests. After each contest, reserve the next practice block for the easiest instructive unsolved task. Add CSES only after that review. Do not promise yourself a fixed number of CSES problems on a contest-heavy week.
